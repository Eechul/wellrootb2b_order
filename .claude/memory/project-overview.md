카페24로 운영되는 **웰루트 B2B(도매)몰**에서, **10개 미만 주문은 수동으로** 해야 한다.
상품마다 페이지를 열고 옵션 고르고 담고 주문서를 채우는 반복 작업 — 이걸 없애는 게 이 프로젝트다.

**해결 방식: 엑셀 입력 → 브라우저 자동화.** 상세는 [[mvp-browser-automation]].

## 범위

- **하는 것:** 엑셀 파싱, 로그인, 상품 담기, 주문서 자동 입력, 라인별 결과 리포트
- **안 하는 것(MVP):** 최종 결제 클릭, 예치금 관리, 거래처별 단가, 다중 사용자/API 서비스

## 어디까지 갔다가 돌아왔나 (중요 — 다시 API를 검토하려 할 때 읽을 것)

처음 구상은 "사장님들에게 발주 API 키를 발급하는 중계 서버"였다. 조사 결과 **예치금 결제 몰에서는 성립하지 않는다**:
카페24에 일반 주문 생성 API가 없고, 우회로인 `orders/migrations`로 주문을 넣으면 **예치금이 차감되지 않는데
예치금 잔액을 증감하는 API도 없다.** 근거와 비교표는 [[architecture-decisions]], 문서 검증 원문은 [[cafe24-api-constraints]].

브라우저 자동화는 실제 결제 화면을 거치므로 예치금·재고·가격이 전부 카페24 정상 처리된다.
**API 우회로보다 정합성이 높고, 개발권한·앱등록·토큰갱신이 전부 불필요하다.** 그래서 MVP는 이쪽이다.

## 사용자 기존 자산

같은 계열 프로젝트가 이미 있어 구조를 참고할 수 있다.
- `cpotalecnt_order_pj` — Electron + Selenium으로 이카운트 ERP에 주문 자동 입력. **구조가 가장 가깝다.**
- `sello_auto_order_processing` — Python/Tkinter + PyInstaller, 엑셀 주문 변환.
